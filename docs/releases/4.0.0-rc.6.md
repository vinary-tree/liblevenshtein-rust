## Release subject and terminology

A **release subject** is the exact set of source bytes and metadata being
validated. A **candidate provenance artifact** identifies that subject before
commits and tags are sealed. A **final attestation** is an append-only record
created after the immutable commits and tags exist; it binds those identifiers
to the candidate's content digests.

The machine-readable candidate record is
[`release/rc6-candidate-provenance.json`](../../release/rc6-candidate-provenance.json).
Its generator and validator are
[`scripts/release-provenance.py`](../../scripts/release-provenance.py).

For every release component the artifact explicitly records the immutable
source commit, package version, coordinated dependency requirements, complete
Cargo feature model, the validated `--all-features` selection, lockfile
digests, and source digest. It separately records `llattice` as an exact build
input because libdictenstein depends on `llattice = 0.1.0`; omitting that fourth
source repository would make the three-component RC tuple irreproducible. The
build-input record includes its commit, version and feature contract,
lockfiles, package file set, and source digest without falsely treating it as
an RC.6 release-family member.

The source checksum algorithm enumerates every tracked or non-ignored
untracked file except the provenance artifact itself. It orders paths by their
encoded bytes and hashes, for each path, the Git-compatible file mode, path,
byte length, and content. Symlinks contribute their link target rather than the
target file. Consequently the checksum is independent of checkout location
but sensitive to content, path, mode, addition, and deletion.

```text
procedure DigestReleaseSubject(repository):
    files := sort(tracked files union non-ignored untracked files)
    remove the generated provenance artifact from files
    digest := SHA-256()
    for file in files:
        record := mode(file), path(file), byte_length(file), bytes(file)
        digest.update(unambiguous_encoding(record))
    return digest
end procedure
```

## Toolchain contract

All three RC repositories declare Cargo `rust-version = "1.95"` and pin the
minimal Rust `1.95.0` toolchain with `rustfmt` and Clippy. Llattice declares its
own lower minimum, Rust `1.70`, but was compiled as part of the RC graph under
the pinned `1.95.0` toolchain. The provenance artifact records the full
compiler and Cargo version output, including compiler commit, host, and LLVM
version. A different toolchain is a different build subject and must not reuse
this evidence.

## Candidate commands

Run the generator only in the coordinated canonical checkout. Omit root
overrides and require both a clean source subject and canonical dependency
paths:

```bash
python3 scripts/release-provenance.py \
  --write \
  --include-package-files \
  --require-clean \
  --require-canonical-paths
python3 scripts/release-provenance.py \
  --include-package-files \
  --require-clean \
  --require-canonical-paths
```

These commands must execute outside an ancestor Cargo configuration that adds
host-global patches, or with an isolated Cargo home. Otherwise Cargo may try to
rewrite an otherwise exact lockfile with host-specific `patch.unused` state.
The default canonical subject also requires sibling directory `../llattice`;
`LLATTICE_ROOT` is an explicit development-only override and is rejected by
canonical-path validation if the libdictenstein manifest itself is not sealed
to `../llattice`.

## Remaining release boundary

No publication is authorized by this development ledger. The local campaign
subject is complete: source work is sealed, canonical paths and lockfiles are
clean, the three RC repositories and exact llattice input are committed, and
the package-file/build/test/lint/formal/provenance gates pass. Publication is a
separate authorized operation. It must first establish any missing registry
inputs, then proceed in dependency order: `vinary-tree-interop`,
`libdictenstein`, and `liblevenshtein`; only public-byte read-back can complete
the tag/registry attestation.
